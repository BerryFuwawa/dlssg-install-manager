# 使用说明

第一次使用请先看[新手一步一步教程](新手教程.md)。本页解释各功能的详细规则，不要求普通用户阅读源码或使用命令行。

## 界面与系统兼容

采用 Windows 11 Fluent 视觉风格：浅色导航、线性图标、蓝色选中标记、圆角窗口/卡片与按钮。Windows 10 使用同样的自绘界面；窗口圆角有 Region 绘制兼容，不依赖 Windows 11 专有背景材质。它是 .NET Framework WinForms 应用，不是 WinUI 3，也不要求安装 Windows App SDK。

拖动顶部标题栏移动窗口；双击标题栏最大化/还原，右上角为最小化、最大化、关闭。窗口边缘支持缩放，按钮可用 Tab 聚焦并按空格触发。操作期间按钮会禁用并显示忙碌反馈；不会自动结束游戏。

支持按显示器 DPI 缩放，不需要把 Windows 缩放改成 100%。字体、控件、表格行高、图标、圆角和间距一起调整；窗口跨不同 DPI 显示器时重新布局，使用固定设计尺寸计算，避免来回拖动后累积放大或缩小。高缩放或小屏幕下窗口限制在工作区内，内容区出现滚动条时可以滚动访问其余按钮，不会强行缩小文字。

左下角“GitHub 仓库”打开 `BerryFuwawa/dlssg-install-manager`。上游 DLL 的项目说明保留在文档内，不再作为侧栏按钮。

## 安装前

先阅读目标游戏对模组、代理 DLL 和反作弊的规定。工具不会检查游戏服务条款，不会绕过反作弊，也不会自动结束游戏。线上/竞技游戏请格外谨慎；无法确认允许修改时不要安装。

将 EXE 放在自己可写的普通目录。首次使用无需管理员权限；若游戏目录不可写或进程受保护，可在确认信任程序后自行选择管理员运行，或者停止安装。不修改系统目录、驱动或安全设置。

## 自动选择与手动选择

在“安装与更新”页点击“检测 GPU · 10 秒”，确认游戏已进入实际画面。初始化计数器与最后解析路径可能额外花少量时间；界面显示的采样实际时间才是采样窗口。后台以单调时钟调度十次批量采样。

列表按十个样本中的平均最忙引擎负载排序，自动选中首项。至少需要三个正负载有效样本，平均负载不低于 0.5%。系统界面、常见浏览器和录屏程序被排除。PID 启动时间变化则拒绝该候选，防止 PID 重用误选。

自动检测只是辅助，不保证最高负载进程一定是游戏。核对程序名称和完整路径。选中其他行会立即更新安装目标，同时撤销之前的退出确认。

如果无法检测或路径不可读，点击“手动选择 EXE”。选择实际渲染程序，不是 launcher、updater、uninstaller 或反作弊启动器。**选好之后就在同一页面继续检查退出并安装，无需返回自动检测。**

## 退出检查与部署

1. 退出游戏，等待实际渲染进程结束。
2. 点击“检查游戏已退出”。仍运行、同名进程路径无法确认时，安装按钮不会启用。
3. 点击“备份并安装 / 更新”，阅读目标目录与风险确认。
4. 工具先检查远程提交，再准备完整缓存；有效缓存不存在且网络失败时，不创建游戏备份、不替换文件。
5. 下载成功后再次检查游戏进程；建立原文件备份并校验，写清单，再检查一次进程才开始替换。
6. DLL 与 INI 部署后分别校验 SHA256；遇到写入失败，尝试还原到安装前状态，并记录回滚结果。

安装与更新都会写入配套的默认 `dlssg_sm86.ini`，不是保留原 INI 的“只换 DLL”操作；原文件先备份，但不会自动合并自定义参数。其他模组占用同名 DLL 时可能冲突，先核对再安装。本版不部署其他名称的代理 DLL，也不会给没有帧生成功能的游戏添加菜单。

安装成功只代表文件部署成功。是否支持游戏、如何在游戏中开启帧生成，请查阅[上游 README](https://github.com/sdli1995/dlssg_for_sm86)与[上游安装说明](https://github.com/sdli1995/dlssg_for_sm86/blob/main/docs/INSTALL.md)。

## 集中缓存

每次实际安装自动查询上游默认分支 HEAD，不依赖固定 `main` 名称。DLL、README、INI 均固定到同一个提交下载。文件格式、大小、本地哈希与配置检查完成后，才把暂存目录切换成正式缓存。

- 提交不变且缓存有效：缓存命中，不重复下载 DLL。
- 提交变化或缓存损坏：重新下载并验证。
- 更新请求失败且旧缓存有效：显示离线警告后使用旧缓存。
- 无有效缓存且联网/验证失败：安全停止。

只保留当前缓存。历史安装前文件留在各次备份里；清单记录安装后哈希和来源提交，不等于保存每一版完整上游包。

## 备份与恢复

“备份与恢复”同时读取文档目录集中备份，以及当前选中 EXE 向上六级目录内的旧版 `DLSS帧生成备份`。请先手动选中旧游戏 EXE，再刷新旧版记录。无效或不受支持的清单不提供恢复入口。

恢复前退出原游戏，选中记录并确认。工具只处理 `version.dll` 与 `dlssg_sm86.ini`，先校验所有原备份，再保存当前文件快照。安装前存在的文件恢复原内容；安装前不存在的文件只有仍与记录的安装后哈希一致时才删除，避免误删其他模组改过的文件。

原备份损坏时停止恢复。恢复过程写入失败会尝试回到恢复前快照。断电、系统故障或进程突然终止不能保证自动回滚完成；保留备份，按“恢复说明.txt”处理，不要直接清空文档目录。

## 游戏设置与日志

在“游戏设置”读取目标文件的实际 SHA256 与最近安装记录。记录版本仅代表上次记录，不凭哈希自动判断陌生文件属于哪个版本。

日志等级：0 关闭、1 仅错误、2 配置与能力、3 详细跟踪。更改前检查游戏退出并集中备份原 DLL 和 INI。游戏重启后生效；上游日志默认位于游戏目录 `dlssg_sm86\logs`。

“操作日志”是管理器本次窗口的记录。可导出 UTF-8 文本；分享前检查本机路径、用户名等内容。工具不自动上传日志。

## GUI 自身更新

默认启动时检查本仓库最新正式 Release。可在“缓存与更新”关闭自动检查；右下角仍可手动检查。

检测到新版后，右下角出现**红点和“存在更新 · v版本号”**。点击并确认，下载到文档目录的“程序更新”，校验发布清单的 SHA256、大小、程序集名称与版本。内置更新助手就绪后当前 GUI 才退出；助手保留旧 EXE，替换成功后重启新版本。

更新目录可以和程序不在同一盘；助手先在目标盘创建经过校验的副本，再执行同卷替换。如果目标目录不可写、旧进程没退出或下载不完整，停止更新并保留原程序。失败时可以到 Releases 手动下载。没有 Authenticode 数字签名；请核对来源与源码，不要绕过系统的安全警告。
