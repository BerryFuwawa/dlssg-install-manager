# 开发与发布

## 构建

Windows x64，.NET Framework 4.7.2+。构建脚本使用 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，仅引用框架程序集；不需要 .NET SDK、NuGet 或 Python。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
powershell -NoProfile -ExecutionPolicy Bypass -File .\screenshots.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\package.ps1
```

`dist/DLSSG-Install-Manager.exe` 为单个可分发 GUI，更新助手已嵌入资源。不要把 `Tests.exe`、测试夹具或 `LiveChecks.exe` 发布给普通用户。

`screenshots.ps1` 编译专用文档渲染器，生成六张 150% DPI 界面 PNG。只操作截图模式中的界面，不联网、不安装、不恢复；红灯为注入的演示版本，文档必须明确标注。`package.ps1` 递归包含文档和截图，便携包中保留相同相对路径，Markdown 阅读器可以离线显示图片。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/Core.cs` | 校验、原子缓存切换、集中备份、部署/回滚、旧清单兼容、恢复与日志设置 |
| `src/Gpu.cs` | PDH 原生批量采样、无效样本过滤、PID 身份校验、原生/WMI 路径查询 |
| `src/Updates.cs` | GUI Releases 检查、更新清单验证、下载、更新助手握手 |
| `src/UpdateHelper.cs` | 等待旧进程退出、同卷替换、旧 EXE 备份和新程序启动 |
| `src/Controls.cs` | 自绘圆角卡片、按钮、进度和焦点反馈 |
| `src/FluentForm.cs` | Fluent 自绘标题栏、窗口拖动/缩放、Win11 原生圆角请求及 Win10 Region 兼容 |
| `src/DpiLayout.cs`、`app.manifest` | PerMonitorV2 声明、96 DPI 设计快照、字体/控件/表格统一缩放、低分辨率滚动兼容 |
| `src/MainForm.cs` | 五个页面、异步任务状态、明确的选择/退出/安装确认流程 |
| `tests/` | 隔离核心测试、界面状态测试、自更新端到端夹具、可选联网/GPU 实测 |

安全边界：只允许管理两种固定文件名；恢复先验证所有原备份；同名进程无法定位时阻止安装；取消不会提交半截缓存；跨实例文件锁覆盖缓存、部署与恢复。缓存、清单与哈希都在同一用户可写目录内，不把它们当防本地恶意篡改的信任根。

## GUI 更新协议

只通过 `https://api.github.com/repos/BerryFuwawa/dlssg-install-manager/releases/latest` 获取正式版。Release 必须同时包含：

- `DLSSG-Install-Manager.exe`
- `update-manifest.json`
- 可选：`DLSSG-Install-Manager-v版本号-portable.zip`

清单由构建脚本从最终 EXE 生成，格式如下：

```json
{
  "Schema": 1,
  "Version": "2.0.0",
  "File": "DLSSG-Install-Manager.exe",
  "Sha256": "64位十六进制SHA256",
  "Size": 123456
}
```

使用三段版本号和 `v2.0.1` 这样的标签。发布前同步 `GuiUpdater.Current`、HTTP User-Agent、`Program.cs` 的 AssemblyVersion / AssemblyFileVersion（四段，如 `2.0.1.0`）、`app.manifest` 的版本和文档版本。清单版本与程序集版本必须匹配；不允许把旧二进制配上新清单冒充更新。

更新助手首先验证父进程路径，写就绪标记，再等待退出；旧进程最多等 60 秒。同一盘创建暂存副本后 `File.Replace`，保留 `.previous-时间.exe`。成功替换后启动新 GUI。如果替换或启动调用失败，会保留/尝试恢复旧 EXE并提示。**不能保证检测新版本启动后的所有运行时故障**；旧 EXE 备份可用于手动回退。

目前没有数字签名、独立签名清单、增量更新或后台静默安装。仅 HTTPS + 固定仓库来源 + SHA256/大小/程序集标识校验。未来若引入签名，必须单独设计受信任公钥与迁移方案。

## 发布步骤

1. 更新版本与 `CHANGELOG.md`，执行 `build.ps1 -Test`。
2. 查看 GUI，确认路径、退出检查、更新红灯和键盘焦点反馈；不要用真实游戏作为写入测试夹具。
3. 执行 `package.ps1`，确认 EXE、清单和 ZIP 一致。
4. 创建新标签与 GitHub Release，上传最终 EXE、清单、ZIP；不要覆盖已发布版本的同名内容。
5. 获取公开 Release，确认附件大小与清单哈希，再用旧版本检查新版本能被发现。

仓库 CI 在 Windows 上执行编译、63 项核心测试、59 项界面/DPI 检查并产出便携包。DPI 回归不改变系统显示设置：直接运行与窗口 DPI 消息相同的布局路径，另注入一次 `WM_DPICHANGED` 验证消息处理。CI 不进行真实游戏部署，也不自动联网拉取上游大 DLL。可选 `tests/LiveChecks.cs` 供维护者手动编译执行，运行前三轮 GPU 实测会占用约 30 秒。

DPI 采用自管理缩放（`AutoScaleMode.None`），避免框架自动缩放与自绘的二次叠加。manifest 声明 PerMonitorV2，旧系统回退 PerMonitor；初始化读取窗口 DPI，`WM_DPICHANGED` 使用建议窗口矩形和目标工作区。每次从 96-DPI 快照重算，不累乘上次取整后的像素值。新增自绘元素和 `Resize` 布局规则必须使用 `Px` / `DrawingScale`；新增字体必须进入快照，不能重新引入固定像素的重置逻辑。
